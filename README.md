# FastAPI Service

## Overview

Production-ready FastAPI service built on Python 3.12+, `uv` for dependency management, and a modular `src/` layout. The service exposes versioned API v1 health probes, a users CRUD REST API, RBAC management endpoints, Alembic migrations, and autogenerated OpenAPI documentation.

## Requirements

- Python 3.12+
- [`uv`](https://github.com/astral-sh/uv)
- Docker (optional)

## Quick Start

```bash
uv sync
cp .env.example .env
docker compose up -d postgres
uv run alembic upgrade head
uv run serve
```

The service starts on `http://localhost:8000`.

## API Documentation

- Swagger UI: `http://localhost:8000/api/docs`
- ReDoc: `http://localhost:8000/api/redoc`
- OpenAPI JSON: `http://localhost:8000/api/openapi.json`

## Authentication Model

Protected endpoints require an `X-User-Id` header containing the UUID of the acting user.

Bootstrap behavior:

- The very first `POST /api/v1/users` request is allowed without `X-User-Id`.
- That first user is automatically assigned the seeded `admin` role.
- After bootstrap, all users and RBAC endpoints require `X-User-Id` plus the relevant permission.

Example:

```bash
curl \
  -H "X-User-Id: <user-uuid>" \
  http://localhost:8000/api/v1/users
```

## Users API

Base path: `/api/v1/users`

- `POST /api/v1/users`
- `GET /api/v1/users?page=1&limit=20`
- `GET /api/v1/users/{user_id}`
- `PATCH /api/v1/users/{user_id}`
- `DELETE /api/v1/users/{user_id}`

Required permissions:

- `POST /api/v1/users` -> `users:create` unless the database has zero users
- `GET /api/v1/users` and `GET /api/v1/users/{user_id}` -> `users:read`
- `PATCH /api/v1/users/{user_id}` -> `users:update`
- `DELETE /api/v1/users/{user_id}` -> `users:delete`

The API enforces unique emails, validates UUID path parameters through FastAPI/Pydantic, returns `404` for missing users, `409` for duplicate emails, `401` for missing/invalid actor headers, and `403` when the actor lacks permission.

## RBAC API

Base path: `/api/v1/rbac`

- `GET /api/v1/rbac/permissions`
- `GET /api/v1/rbac/roles`
- `POST /api/v1/rbac/roles`
- `GET /api/v1/rbac/roles/{role_id}`
- `PATCH /api/v1/rbac/roles/{role_id}`
- `DELETE /api/v1/rbac/roles/{role_id}`
- `POST /api/v1/rbac/roles/{role_id}/permissions`
- `DELETE /api/v1/rbac/roles/{role_id}/permissions/{permission_id}`
- `GET /api/v1/rbac/users/{user_id}/roles`
- `POST /api/v1/rbac/users/{user_id}/roles`
- `DELETE /api/v1/rbac/users/{user_id}/roles/{role_id}`

Seeded permissions:

- `users:create`
- `users:read`
- `users:update`
- `users:delete`
- `rbac:read`
- `rbac:write`

The seeded `admin` role receives all seeded permissions.

## Health Check Endpoints

### Liveness

```bash
curl http://localhost:8000/api/v1/health/live
```

Example response:

```json
{
  "status": "ok",
  "timestamp": "2026-05-26T12:00:00Z"
}
```

### Readiness

```bash
curl http://localhost:8000/api/v1/health/ready
```

Example response:

```json
{
  "status": "ready",
  "version": "1.0.0",
  "uptime_seconds": 1.234,
  "timestamp": "2026-05-26T12:00:00Z",
  "components": [
    {
      "name": "application",
      "status": "healthy",
      "latency_ms": 0.0,
      "details": "FastAPI application startup completed."
    }
  ]
}
```
