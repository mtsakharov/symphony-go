# FastAPI Service

FastAPI users service with health probes, versioned REST endpoints, SQLAlchemy persistence, and Alembic migrations. Dependencies and developer tooling are managed with `uv`, and the application runs on Python 3.12.

## Features

- Health endpoints for liveness and readiness checks
- Versioned API under `/api/v1`
- CRUD endpoints for users with duplicate-email protection
- SQLAlchemy models and Alembic migrations
- OpenAPI, Swagger UI, and ReDoc generated by FastAPI
- Test suite covering the API layer and users service

## Requirements

- Python 3.12
- [`uv`](https://docs.astral.sh/uv/)
- Docker and Docker Compose, if you want to run PostgreSQL locally

## Configuration

The application reads settings from environment variables and will also load `.env` automatically.

Copy the example file before starting the app:

```bash
cp .env.example .env
```

Available settings:

| Variable | Default | Purpose |
| --- | --- | --- |
| `APP_NAME` | `FastAPI Service` | OpenAPI title and service name |
| `APP_VERSION` | `1.0.0` | OpenAPI and readiness version |
| `ENVIRONMENT` | `dev` | Environment label used in OpenAPI server metadata |
| `DEBUG` | `false` | Enables uvicorn reload when `true` |
| `HOST` | `0.0.0.0` | Bind host |
| `PORT` | `8000` | Bind port |
| `API_V1_PREFIX` | `/api/v1` | Prefix for versioned routes |
| `DATABASE_URL` | `postgresql+psycopg://postgres:postgres@localhost:5432/fastapi_service` | SQLAlchemy connection string |

## Quick Start

1. Install dependencies:

```bash
uv sync
```

2. Start PostgreSQL:

```bash
docker compose up -d postgres
```

3. Apply migrations:

```bash
uv run alembic upgrade head
```

4. Start the API:

```bash
uv run serve
```

The service listens on `http://localhost:8000`.

## Health Endpoints

Liveness probe:

```bash
curl http://localhost:8000/api/v1/health/live
```

Readiness probe:

```bash
curl http://localhost:8000/api/v1/health/ready
```

The readiness endpoint returns `200` with `status: "ready"` when startup completed, and `503` with `status: "not_ready"` when the app is not ready to accept traffic.

## Users API

Base path: `/api/v1/users`

- `POST /api/v1/users`
- `GET /api/v1/users?page=1&limit=20`
- `GET /api/v1/users/{user_id}`
- `PATCH /api/v1/users/{user_id}`
- `DELETE /api/v1/users/{user_id}`

Create a user:

```bash
curl -X POST http://localhost:8000/api/v1/users \
  -H "Content-Type: application/json" \
  -d '{
    "email": "user@example.com",
    "first_name": "Jane",
    "last_name": "Doe"
  }'
```

List users with pagination:

```bash
curl "http://localhost:8000/api/v1/users?page=1&limit=20"
```

The API returns `409` when creating or updating a user with a duplicate email, and `404` when reading, updating, or deleting a missing user.

## Testing

Run the test suite with:

```bash
uv run pytest
```

Tests use a temporary SQLite database, so they do not require the local PostgreSQL container.

## Docker

To run the database and API together in containers:

```bash
docker compose up --build
```

The `fastapi-service` container reads configuration from `.env`, and the `postgres` container exposes PostgreSQL on `localhost:5432`.
